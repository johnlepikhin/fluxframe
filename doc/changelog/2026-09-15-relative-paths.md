# 2026-09-15 — Относительные пути считаются от файла конфигурации

## Почему

Относительные пути в конфиге — `model` в секции `mask`, `path` у `image_fill`,
`idle.placeholder_path` — открывались относительно рабочего каталога демона.
Один и тот же конфиг работал при запуске из одного каталога и ломался при
запуске из другого, а сервису приходилось задавать рабочий каталог вручную.
`idle.placeholder_path` вообще требовал абсолютного пути.

## Что изменилось

- Относительный путь теперь означает «рядом с файлом конфигурации»: он
  разрешается от каталога, где лежит конфиг (`--config` или
  `$XDG_CONFIG_HOME/fluxframe/fluxframe.toml`). Абсолютные пути не меняются.
- Правило одно для всех мест, где открывается файл: сборка пресета при старте,
  `set_preset`, `reload`, `set_chain`, живой `set` из GUI или сокета, плейсхолдер
  idle-режима и `fluxframe check`.
- В самом конфиге пути остаются как написаны: `get_config` и сохранение пресета
  из GUI не превращают их в абсолютные.
- Без файла конфигурации (`--no-default-config` без `--config`) пути, как и
  раньше, считаются от рабочего каталога.
- `control.socket_path`, устройства и `fluxframe benchmark --model` не
  затронуты.

## Миграция

Если конфиг содержит относительные пути и демон запускался из каталога, отличного
от каталога конфига (например, из каталога репозитория с моделями в `./models`),
после обновления пути начнут указывать в каталог конфига. Перед обновлением либо
положите файлы рядом с конфигом, либо замените пути на абсолютные. Проверка:

```bash
fluxframe check --config ~/.config/fluxframe/fluxframe.toml
```

`WorkingDirectory` в описании сервиса больше не нужен.
