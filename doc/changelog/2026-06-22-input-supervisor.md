# 2026-06-22 — Always-on loopback + input-acquire backoff (§A/§B)

## Почему

Если `/dev/video0` была занята (например, Chrome держал её напрямую) **на старте**
демона, FluxFrame не мог построить вход, падал в краш-луп и **вообще не поднимал**
loopback `/dev/video10` — поэтому виртуальная камера не появлялась в Chrome. Раньше
жизнь loopback-производителя была сцеплена с захватом камеры.

## Что изменилось

- **Output (loopback) поднимается ПЕРВЫМ**, до захвата камеры. `/dev/video10` сразу
  анонсирует CAPTURE-caps и стримит placeholder — устройство видно в Chrome даже когда
  камера занята/отсутствует.
- **Захват входа с backoff (supervised-путь):** при `idle.enabled` + loopback-sink +
  v4l2-камере занятая/отсутствующая камера не роняет демон — он стримит placeholder и
  ретраит захват с экспоненциальным backoff (по умолчанию 0.5с → ×2 → 5с), **бесконечно**.
  Лог занятости — один раз (затем debug), без флуда. Перманентные ошибки (нет элемента,
  битый формат/конфиг) по-прежнему падают быстро.
- **`detect_native_mode`** теперь выполняется на каждой попытке захвата (внутри билдера
  входа), а не один раз до построения — поэтому он не блокирует подъём loopback, когда
  камера занята.
- **Новые config-knob'ы** в `[input]`: `acquire_backoff_base_ms` (500),
  `acquire_backoff_max_ms` (5000). `#[serde(default)]` — старые TOML не ломаются.
- **Новые счётчики:** `input_acquire_attempts_total`, `input_acquire_failures_total`
  (растущий разрыв при плоском `frames_in` = камера контендится).

## Действия оператора

- Обычно ничего. При желании настройте `input.acquire_backoff_base_ms` /
  `acquire_backoff_max_ms` в `fluxframe.toml`.
- Always-on поведение активно только при `idle.enabled = true`.

## Ограничения (известно)

- При **выдёргивании камеры во время стрима** (mid-stream input death) видео-выход
  кратко мигает на пересоздании (доли секунды) — output пересобирается на повторном
  входе через `run_auto`. Полностью без блипа потребует развязки slot от InputPipeline
  (отложено: `LatestFrameSlot` создаётся внутри `InputPipeline::build`).
- При `device = "auto"` и **полностью отсутствующей** камере (узла нет) loopback
  поднимется только после того, как `run_auto` найдёт устройство. Кейс «камера есть, но
  занята» (баг пользователя) — покрыт.
- Verify на железе обязателен (камера + Chrome) — см. README → Troubleshooting.
